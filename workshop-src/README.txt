2026 워크샵 프로그램 및 조배정 — IT 인수인계 안내
=====================================================

이 앱은 무엇인가
----------------
참석자가 로그인 없이 자기 이름만 검색하면 배정된 조와 전체 워크샵 일정을 확인할 수 있는
1페이지짜리 웹앱입니다. 화면 상단에 Program / Grand Hall / 석식 세 개의 탭이 있고, Program
탭에는 일정표와 강사진 소개가, Grand Hall과 석식 탭에는 각각 세미나 테이블 조배정과
바베큐(석식) 조배정이 이름 검색 방식으로 표시됩니다. 백엔드 서버나 데이터베이스, 로그인이
전혀 필요 없는 순수 정적 파일 하나로 동작합니다.

바로 올려야 할 파일
--------------------
이 폴더의 index.html 파일 하나가 실제로 호스팅할 완성된 파일입니다. Rollbook 관리자
사이트에 이 파일 하나만 올리면 그대로 동작합니다. source 폴더는 나중에 내용을 직접
수정하고 싶을 때 쓰는 원본 소스이고, 사이트에는 올릴 필요가 없습니다.

외부에서 불러오는 리소스
------------------------
index.html은 두 개의 외부 리소스를 브라우저에서 직접 불러옵니다.
1) fonts.googleapis.com — 화면에 쓰이는 글꼴(Noto Sans KR, IBM Plex Mono)
2) cdnjs.cloudflare.com — 엑셀 업로드/파싱에 쓰이는 SheetJS 라이브러리
사내 방화벽이나 사이트의 Content-Security-Policy 설정이 외부 스크립트를 막아둔 상태라면,
이 두 도메인을 허용 목록에 추가해 주셔야 정상적으로 동작합니다.

데이터(엑셀) 갱신 방법 — 관리자 패널
-------------------------------------
화면 맨 아래쪽에 작게 있는 "관리자" 글자를 누르면 숨겨진 관리자 패널이 열립니다.
1. "3.참석명단", "1.스케줄", "강의목록"(또는 "강의프로그램") 시트가 들어있는 엑셀 파일을
   선택하고 "미리보기"를 누릅니다.
2. 기존 조배정과 비교해서 몇 명이 그대로 유지되는지, 몇 명이 새로 추가/제외되는지,
   조별 인원 수가 화면에 표시됩니다. 조배정 로직은 사람이 한 번 배정받은 조를 최대한
   유지하도록 설계되어 있어서 — 참석자가 자기 조를 외웠는데 갑자기 다른 자리로 바뀌는
   상황이 생기지 않습니다. 명단이 크게 바뀌어 처음부터 다시 배정하고 싶을 때만
   "기존 조배정을 무시하고 처음부터 새로 배정" 체크박스를 사용하시면 됩니다.
3. 내용을 확인한 뒤 버튼을 누르면 데이터가 반영됩니다.

이 버튼의 동작이 원래 있던 화면(Claude 아티팩트)과 다릅니다 — 원래는 "게시하기"를 누르면
스스로 새 버전을 저장하는 기능이 있었지만, 이 기능은 Claude가 호스팅하는 화면 안에서만
동작합니다. 이 index.html 파일은 그런 환경이 아닌 것을 자동으로 인식해서, 버튼 이름이
"업데이트 파일 다운로드"로 바뀌어 있습니다. 이 버튼을 누르면 새 데이터가 반영된 완성된
index.html 파일이 브라우저에 새로 다운로드됩니다 — 이 파일로 사이트에 이미 올라가 있는
index.html을 교체해 주시면 됩니다. 파일을 바꾸는 것은 자동으로 이루어지지 않고,
매번 다운로드 후 수동으로 교체해 주셔야 합니다.

조배정 로직 참고
-----------------
Grand Hall(세미나 테이블)과 석식(바베큐)은 완전히 독립된 두 개의 배정이고, 계산 방식도
다릅니다.

Grand Hall은 엑셀의 "4.조배정" 시트에 이미 짜여 있는 조 배치를 그대로 읽어서 화면에
반영합니다 — 앱이 알아서 조를 새로 짜는 것이 아니라, "4.조배정" 시트에 사람이 직접
정리해 둔 내용을 그대로 옮겨오는 방식입니다. "1조", "2조"처럼 번호가 있는 조뿐 아니라
"QRM", "안내데스크 조"처럼 번호 없이 이름만 붙은 그룹도 시트에 있는 그대로 자동으로
인식해서 함께 표시합니다 — 그룹 이름이 바뀌거나 새로운 이름의 그룹이 추가되어도 앱
코드를 고칠 필요 없이 "4.조배정" 시트만 정리하면 그대로 반영됩니다. 그래서 "4.조배정"
시트에 없는 사람(아직 자리 배정이 안 된 신규 참석자 등)은 Grand Hall에서는 검색되지 않고,
석식에서만 검색됩니다(석식은 아래처럼 별도로 자동 계산되기 때문입니다). 참석자별 AI 활용
경험 여부는 "4.조배정" 시트에서 성명 칸이 노란색으로 칠해져 있는지로 판단합니다 — 이
표시 방식이 바뀌면 인식이 안 될 수 있으니 참고해 주세요. (다만 이 값은 조배정을 섞을 때
내부적으로만 쓰이고, 화면에는 AI 유경험자 표시를 따로 하지 않습니다.)

주의: 참석명단만 바뀌고 "4.조배정" 시트는 이전 그대로일 때 — 새 참석자가 "4.조배정"에는
아직 없는 상태로 앱에 그대로 반영하면, 그 사람은 Grand Hall에서 빠지게 됩니다. 이런
경우에는 "4.조배정" 시트에 새 인원을 직접 추가해서 올리시거나, Claude에게 "참석명단이
바뀌었으니 조배정을 다시 해달라"고 요청해서 (기존 조는 그대로 유지하고 추가된 인원만
본부·직급·AI 경험을 섞어서 배정하는 방식으로) 반영하는 방법이 있습니다. QRM/S조처럼
번호가 없는 특별 그룹은 이 자동 배정 대상에서 제외하고 그대로 유지해달라고 함께
말씀해 주시면 됩니다.

석식(바베큐)은 기본적으로 "3.참석명단"의 전체 참석자를 대상으로 비슷한 직급끼리
가나다순으로 묶는 방식으로 앱이 자동 계산합니다. 새 엑셀이 올라와도 기존 배정에서
최대한 적게 바뀌도록(최소 변경) 계산됩니다.

다만 "4.조배정" 시트 안에는 Grand Hall 표 아래쪽에 "석식" 글자가 들어간 제목 셀로
시작하는 두 번째 좌석표(현재는 비어 있음)가 함께 들어 있습니다. 이 표는 Grand Hall과
완전히 똑같은 형식(직위/성명/성별/본부, "N조 (M명)")으로 만들어져 있고, 앱은 이 표에
누군가의 이름이 한 명이라도 채워지면 그때부터 자동으로 "이 표를 그대로 읽어서 석식에
반영하는 방식"으로 전환됩니다 — Grand Hall이 "4.조배정"을 그대로 옮겨오는 것과 똑같은
방식입니다. 표가 아직 비어 있는 동안에는(지금 상태) 이 표는 무시되고 위에서 설명한
자동 계산 방식이 그대로 쓰이니, 지금 당장 석식 검색이 안 되는 일은 없습니다. 나중에
이 표에 사람을 채워 넣고 엑셀을 다시 올리면, 코드를 고칠 필요 없이 자동으로 그 표
기준으로 석식이 반영됩니다.

Program 탭의 일정표는 "1.스케줄" 시트를 그대로 읽어서 반영합니다. 일정표에 표시되는
빨간 동그라미 "출석체크" 표시도 시트에서 자동으로 인식합니다 — 해당 행 근처 빈 칸에
"출석1", "출석2"처럼 "출석"+숫자가 적혀 있으면 그 행에 표시가 붙습니다. 그래서 나중에
출석체크가 필요한 시간이 추가/삭제되더라도, "1.스케줄" 시트에서 그 표시만 적절히
넣거나 지우면 앱에 자동으로 반영되고, 코드를 고칠 필요가 없습니다.

나중에 화면 디자인이나 로직을 직접 수정하고 싶을 때
------------------------------------------------------
source 폴더의 inner.html이 화면의 원본 템플릿이고, build.py가 이 템플릿과
people.json / program.json / dinner.json / groupinfo.json(현재 데이터)을 합쳐서
완성된 index.html을 만들어내는 파이썬 스크립트입니다. Python 3가 설치되어 있으면
source 폴더 안에서 "python3 build.py"를 실행하는 것만으로 새 index.html이
생성됩니다. inner.html의 코드나 디자인(CSS)을 고친 뒤 이 스크립트를 다시 실행하면
됩니다.

QR 코드 관련
------------
이 앱의 주소로 QR 코드를 만들어 명찰 뒤에 인쇄하면, 참석자가 로그인 없이 QR을 찍는 것만으로
바로 이 화면이 열리도록 하는 것이 목표입니다. 참고로 "QR을 찍으면 실제로 이렇게 보인다"를
보여드리는 데모 페이지(qr_scan_preview.html)를 별도로 함께 보내드렸습니다 — 실제 화면과
동일하게 동작하니 보고 자료로 활용하시면 됩니다.
